# Imagen 参数编辑与交互升级草案

状态：原始设计草案，2026-10-13；用户已批准尝试修改。参数编辑、草稿/预设、蒙版上传和设置复用已落地，实际范围与验证见[升级说明](parameter-editing-upgrade.zh-CN.md)。编辑持久化任务、流式、取消和画笔仍属后续计划。下文的“现状”记录改造前的问题。

推荐方向：把 Imagen 升级为「可选、可输入、可复用」的图像工作台。常用参数直接可见，进阶参数按用途展开；生成与编辑共享同一套参数规则，每次任务保留完整设置。

[打开交互原型](prototypes/parameter-workspace.html) · [查看桌面预览图](prototypes/parameter-workspace-desktop.png)。原型使用本地示例数据，可体验输入、联动、模式切换、预设、设置复用与请求预览，不连接生图服务。

## 1. 现状与问题归属

| 已核对的现状 | 对用户的影响 | 应修改的层 |
| --- | --- | --- |
| `ParameterControls.vue` 只有模型、尺寸、质量、格式、数量、审查；五个选择控件都是原生 `select` | 候选列表之外的值无法填写 | 共享参数组件 |
| `backend/schemas.py` 用候选列表校验模型、尺寸、质量、格式、背景与审查 | 单独增加前端输入仍会被后端拒绝 | 后端请求契约；区分建议值与真正约束 |
| 两个表单在配置变化时，把列表之外的值替换成候选值；数量输入和提交都会截断 | 自定义值会丢失，错误可能被自动掩盖 | 表单初始化、校验和序列化 |
| 生图链路已有 `background`，前端类型和控件未开放；编辑链路没有该参数 | 后端能力无法完整操作 | 共享类型、两个请求入口、客户端封装 |
| Python 客户端已有编辑 `mask`，HTTP 接口和页面未接入 | 无法在页面指定局部编辑范围 | 编辑上传与素材处理 |
| 压缩、输入保真度等 SDK 参数未穿过客户端封装 | 高级参数无法实际生效 | 客户端调用边界 |
| 两个表单把提示词和设置保存在组件局部，`ModePanel.vue` 使用 `v-if/v-else` 切换 | 切换模式会重建表单，容易丢失草稿 | 现有 Pinia store 的草稿状态 |
| 历史图片只保存部分参数；「复用」只传提示词 | 无法完整恢复一次生成设置 | 任务/结果记录与复用动作 |
| 生图任务持久化，编辑仍是同步请求；忙碌时表单整体禁用 | 编辑刷新后无法按现有任务机制恢复，等待期间无法准备下一次修改 | 任务生命周期与草稿/任务快照的分工 |
| `moderation: "none"` 被客户端省略，没有发给上游 | 「审查：无」容易被理解为关闭上游审查 | 字段文案及省略语义 |
| 生图提示词在请求模型中限制为 4000 字符，编辑提示词没有同样的长度规则 | 输入体验与限制不一致 | 后端统一的输入长度政策 |

这是参数契约与交互状态的问题。修复应覆盖页面 → 后端 → SDK → 任务/历史整个链路。

## 2. 所有下拉框的统一交互

所有现有和新增的下拉选择框采用同一个**可编辑组合框**，包括模型、尺寸、质量、格式、背景、审查、输入保真度、风格、响应形式以及预设选择。

1. 输入区域始终可以直接键入、粘贴和修改；右侧箭头展开候选列表。
2. 列表支持搜索，保留原始 API 值，旁边显示中文解释，例如「高 · high」。
3. 当输入不在列表中时，显示「直接使用“输入值”」；确认后保留原值并标记「自定义」。候选列表是建议来源。
4. 清晰区分「服务默认（不发送该参数）」「自动 · auto」和具体值。`auto` 是真实请求值；空白代表可选参数未指定，必填参数空白时显示错误。
5. 支持方向键选项、Enter 确认、Esc 收起、Tab 正常移动焦点。输入法选词时的 Enter 不触发表单提交；提供 combobox/listbox 语义、可见焦点和错误关联。
6. 自定义值经本地类型和资源约束校验后传给配置好的服务。服务拒绝时保留输入，并说明失败字段及原因；不替换值、不自动去掉参数重试。
7. 配置加载、切换模式、刷新、复用、保存预设、导出和任务恢复均保留自定义值。首次初始化才应用默认值。
8. 预设名称输入未知名称时，用当前设置另存为新预设；选择已有名称才应用对应设置。失焦不覆盖表单。

格式等字段仍受实际处理能力约束：例如用户可输入 `jpeg` 或 `webp`，输入应用无法保存的格式时要给出明确错误。允许直接输入应与真实能力校验一起完成。

## 3. 参数覆盖范围

以下是面向用户的完整编辑范围。「服务默认」均表示不发送该可选参数。具体服务、模型与接口支持范围在接入时验证。

| 分组 | 字段 | 编辑方式与建议值 | 生效规则 |
| --- | --- | --- | --- |
| 提示词 | `prompt` | 多行编辑、字数、清空撤销、模板、独立生成/编辑草稿 | 后端统一输入长度政策；不自动改写或翻译用户内容 |
| 基础 | `model` | 可输入组合框；使用后端配置的候选模型 | 自定义名称原样提交，不用名称关键词推断能力 |
| 基础 | `size` | 组合框：`auto`、现有尺寸；另提供宽/高数字输入、交换方向、比例快捷项 | 宽高与 `WIDTHxHEIGHT` 是同一个值的两种视图；本地校验语法，服务校验真实分辨率范围 |
| 基础 | `quality` | `auto`、`low`、`medium`、`high`；可输入服务支持的其他值 | 按接口真实支持提交，显示质量与耗时的定性说明 |
| 基础 | `n` | 可直接输入的整数框、增减按钮 | 本地 `max_n` 与上游数量限制分别说明；超限显示错误，保留原值 |
| 输出 | `output_format` | `png`、`jpeg`、`webp`；可输入 | 按实际文件类型保存；明确格式与透明度、压缩的关系 |
| 输出 | `background` | 服务默认、`auto`、`transparent`、`opaque`；可输入 | 生成和编辑均接入；透明背景依赖模型支持及 PNG/WebP |
| 输出 | `output_compression` | 可选数字框 + 滑杆，参考范围 0–100 | 只对支持压缩的输出格式发送；切回 PNG 时不发送该项，保留草稿值并说明 |
| 编辑 | `images` / `image_ids` / `source_order` | 上传、拖放、粘贴、历史图片加入；拖拽和按钮排序 | 清晰显示「输入图片」及最终顺序；上传后默认加入输入列表，允许撤销 |
| 编辑 | `mask` | PNG 蒙版上传、透明区域叠加预览、清除 | 绑定第一张输入图；校验实际图片、尺寸和允许的文件大小；调整首图后重新核验 |
| 编辑 | `input_fidelity` | 服务默认、`low`、`high`；可输入 | 仅编辑使用；解释为对输入图特征的保留程度，支持范围待接入验证 |
| 进阶 | `moderation` | 服务默认、`auto`、`low`；兼容服务扩展可输入 | 原 `none` 映射为服务默认，不宣称关闭审查；生成与编辑分别验证上游接口支持 |
| 进阶 | `style` | 服务默认、`natural`、`vivid`；可输入 | 展示为有条件能力；仅在用户指定且所用接口支持时发送 |
| 进阶 | `response_format` | 服务默认、`b64_json`、`url`；可输入 | 显示适用范围；当前下载封装已识别两种响应，但仍需模型支持 |
| 请求 | `timeout` | 服务默认、秒数输入 | 与图像参数分开保存；正数，受后端资源政策限制；超时不自动重新生图 |
| 请求 | `stream` | 开关 | 接入真实事件消费和任务更新后开放；开关直接对应布尔值 |
| 请求 | `partial_images` | 服务默认或整数输入，SDK 参考 0–3 | 仅启用并接入流式响应时发送；不以计时器假装上游进度 |
| 扩展 | `extra_body` | 键值编辑、JSON 编辑、导入/导出 | 用于配置服务明确支持的扩展字段；展示最终请求，不覆盖专用控件中的字段 |
| 本地 | 预设名称、结果下载名称 | 名称可输入，预设列表可选 | 只影响本地设置管理和下载名称，不作为图像生成参数发送 |

`API key`、服务地址、身份字段、任意请求头、服务器文件路径和输出目录由后端管理。参数扩展仅进入图像请求体；与已有字段重名时提示用户回到对应控件编辑。

`seed`、采样器、步数等应依据兼容服务文档作为扩展字段使用。它们不属于本次已核对的通用 Images 参数。

## 4. 人性化工作台

### 参数有层次，也容易查找

- 保留现有三栏工作台：左侧提示词与参数、中间结果、右侧历史。继续支持面板宽度调整。
- 左侧优先显示提示词、模型、尺寸、质量、格式、数量；「输出设置」「编辑设置」「高级与扩展」分组展开。
- 提供参数搜索；搜索结果可以直接编辑，并展开所在分组。提交区始终可见，展开高级项后不用滚回页面底部。
- 每个字段展示短中文说明、原始值、默认/自定义状态和具体错误；无效字段位于折叠区域时自动展开并定位。
- 尺寸旁显示比例和像素数；质量、数量和尺寸只给出有依据的耗时提示。未配置计费信息时不展示金额估算。

### 草稿、预设和完整复用

- 将生成与编辑的提示词和设置草稿放入现有 store，各自保存；模式切换时保留。
- 本地自动保存文本与参数，明确显示保存状态，并提供清除草稿。刷新后恢复；上传 `File` 不假装可自动恢复，缺失素材明确要求重新添加。历史图片可按 ID 恢复，文件被删时说明。
- 提供「快速试图」「高质量输出」「横向构图」等可查看的参数预设；预设不改写已有提示词。透明素材预设只在服务确认支持后提供。
- 每个字段可恢复服务默认，整组可重置；应用预设/导入/复用后提供一次撤销。切换模型时保留设置，指出已确认的不兼容项。
- 结果提供「复用提示词」「复用完整设置」「继续编辑」。复用完整设置恢复原模式、提示词、全部参数和可恢复的素材来源；旧记录仅恢复实际存在的字段，并注明缺失项。
- 自定义预设可命名、更新、另存、导入和导出。未知预设名按保存动作处理，不发送到上游。

### 等待和出错时仍可操作

- 点击生成/编辑时，后端记录该次请求的不可变快照；草稿继续可编辑。界面分别显示「本次任务设置」和当前草稿，避免用户误认为改动已影响运行中的任务。
- 默认仍保持现有单个活动任务策略；有活动任务时提交按钮说明原因。扩展多任务队列之前，不增加隐式排队行为。
- 生图与编辑统一使用持久化任务；编辑上传素材在任务结束前由后端保管，刷新后可以恢复任务和失败信息。
- 展示排队、运行、保存、完成和失败的真实状态，以及已等待时间。只有上游提供有效进度时才显示百分比。
- 错误留在字段旁和失败任务详情中，支持修改后手动再提交。网络中断后优先恢复原任务状态，避免重复产生请求。
- 「取消」先明确实现语义：上游支持取消才可称取消生成；只断开本地连接时使用「停止等待」，说明任务仍可能完成并产生费用。该能力在验证后增加。

### 素材和结果更顺手

- 图片上传后直接进入输入列表，取消现有「先上传、再添加到编辑队列」的必经步骤；在列表里直接查看尺寸、来源、顺序与移除。
- 粘贴图片仅在编辑输入区域或明确的粘贴动作中接入，不抢占提示词粘贴。
- 蒙版显示实际透明区域，明确「透明处编辑、首图对应」。首期支持上传，后续再加画笔与撤销/重做。
- 结果保留已有下载、缩放、全屏和站点媒体库发布入口；增加完整设置查看、复用和多结果切换。
- 历史增加提示词搜索和模式/模型/日期筛选；删除使用明确对象的确认，只有确实可恢复时才提供撤销。
- 小屏单栏布局；参数区、结果、历史顺序明确，操作区不遮挡输入。`Ctrl/Cmd + Enter` 仅在校验通过且允许提交时执行。

## 5. 最小结构调整

| 修改点 | 建议 |
| --- | --- |
| `ParameterControls.vue` | 保留为生成/编辑共享入口；提取一个可复用的 `EditableCombobox`，按用途分组；数字使用受控输入和提交前校验 |
| `GeneratePanel.vue` / `EditPanel.vue` | 从 store 读取各自草稿；删除用候选列表覆盖自定义值的 watcher 和静默数量截断；模式差异只体现在编辑素材及专属参数 |
| `webui/src/types/image.ts` | 共用图像选项；编辑选项在同一基础上增加 `input_fidelity` 等专属字段；可选项统一使用省略语义 |
| `backend/schemas.py` | 复用现有 `ImageOptions`，编辑继承公共选项；建议列表不再充当通用白名单。保留类型、范围、文件与权限约束；生图和 multipart 编辑使用一致校验与字段级错误 |
| `backend/config.py` | 继续作为候选值、应用默认和本地资源上限的来源；模型能力说明只有已核对时提供，记录来源，不复制一套前端猜测规则 |
| `backend/app.py` / `image_service.py` | 补齐生成与 multipart 编辑的公共字段、蒙版和扩展参数；复用统一验证/请求构造；同步入口与任务入口处理同样的参数 |
| `gpt_image_client.py` | 在已有两个调用方法中补齐真正接入的参数；显式构造最终请求、检查扩展重名，分离请求设置与图像参数；用同一解析路径处理返回图像 |
| `imageStore.ts` | 管理两个草稿、预设、校验反馈；运行任务快照与可变草稿分别保存；复用现有任务轮询 |
| `job_store.py` / `image_store.py` | 任务保存完整有效请求与请求设置；结果关联任务及完整选项。继续使用现有文件存储，兼容读取旧记录 |
| 历史与错误组件 | 复用动作传递完整记录；字段级错误来自后端验证和可识别的服务错误，未知服务错误显示原任务详情，不靠文本猜测字段 |

保持一个不变量：**用户看到并确认的有效参数，就是实际发送且被任务记录的参数。** 若因模式或输出格式使某项不参与请求，应明确展示「本次不发送」及原因，草稿值继续保留。

参数 JSON 视图编辑同一个草稿。模型、提示词、数量、素材引用等专用字段通过同一规则校验；`extra_body` 只保留未被专用字段占用的扩展值。服务器的凭据、地址、身份和文件系统设置不进入导出内容。

## 6. 推荐实施顺序

| 批次 | 可验收交付 |
| --- | --- |
| 第一批：参数编辑闭环 | 所有下拉可输入；宽高与自定义尺寸；背景、压缩、保真度、蒙版上传、审查语义；公共请求契约；正确的字段错误；两个模式草稿保留 |
| 第二批：重复工作更省心 | 本地草稿恢复、自定义预设、导入导出、完整历史设置和复用；编辑持久化任务；任务运行期间可准备草稿；素材粘贴与排序 |
| 第三批：经验证的高级能力 | 风格、响应形式、请求超时与扩展字段编辑；真实流式响应及部分图像；历史筛选和结果比较；按验证结果决定取消和蒙版画笔 |

先完成常用参数的实际生效，再接入需要新任务生命周期支持的能力。各批次都完成端到端验证后开放对应控件；草案覆盖最终范围。

## 7. 验收条件

1. 每个选择控件均能直接输入；鼠标、键盘、中文输入法和触摸可用。两种模式使用相同交互。
2. 使用模拟兼容服务验收列表外的模型、尺寸、质量与扩展值：前端保留、后端接收、实际请求一致、历史能完整恢复。对真实服务另验收其已支持的参数。
3. 数字输入允许暂时清空或输入不完整值；提交时显示错误，不能把超限数自动改成另一个数。
4. 服务默认省略、`auto`、`0`、`false`、具体值正确区分；原 `none` 记录按已有省略语义读取。
5. PNG 的压缩项不发送；JPEG 的透明背景错误明确；切换回兼容设置时保留原稿。未确认的模型能力不被编造为支持或不支持。
6. 生成 JSON、后台生成任务、编辑 multipart 和编辑任务使用同一公共参数规则；无效编辑请求返回字段错误，不能因路由内校验变成泛化 500。
7. 上传图片与历史图片混合输入、顺序、蒙版对应首图和保真度均可追踪；任务在刷新后恢复，缺失上传素材的草稿给出说明。
8. 切换模式、配置刷新、浏览器刷新、应用预设、完整复用均保留自定义参数；运行任务快照不被草稿改动影响。
9. 服务拒绝自定义值时保留用户输入；手动修正前不再次提交，不隐藏或自动删除失败参数。
10. 结果文件真实类型与下载扩展名一致；新记录包含有效选项，旧记录正常显示且不伪造缺失设置。
11. 独立 WebUI 与 PersonalStation 嵌入入口都验收；保持既有下载与媒体库发布可用。
